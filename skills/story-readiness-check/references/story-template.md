# Story template (Jira / Azure DevOps)

Use it to flag missing sections. Do not force the team to rewrite a good story into this shape.

```
Summary: <verb + object, e.g. "Guest cancels a booking">

User story
As a <role>
I want <action>
So that <benefit>

Business context
<why now, who asked, metric that shows success>

Requirements
R1. ...
R2. ...

Acceptance criteria
Rule 1: <one sentence>
  Example 1.1: Given ... When ... Then ...
  Example 1.2: ...
Rule 2: ...

Out of scope
- ...

Dependencies
- APIs, other teams, feature flags, data migrations

Designs / links
- mockups, API contract, related tickets

Open questions
- Q1 (Blocking / Non-blocking) ...
```

Size rule of thumb (Example Mapping): more than 3–4 rules → the story is probably too big; split it.
